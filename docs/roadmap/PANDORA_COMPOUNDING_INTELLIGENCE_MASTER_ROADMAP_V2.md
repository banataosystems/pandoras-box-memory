## 1. North-star objective

Build Pandora into a continuously compounding, evidence-governed operating intelligence system that becomes more aware, more useful, and more strategically capable whenever meaningful data enters the ecosystem, while never allowing unverified information, model speculation, secrets, stale state, or unsafe self-modification to silently become canonical truth.

Pandora must preserve everything valuable, learn from outcomes, reuse lessons across projects, detect contradictions and drift, keep a current world model, and turn repeated successful procedures into reusable ProjectOS skills. It must remain fail-closed for production, security, privacy, destructive, financial, legal, regulatory, and other high-risk actions.

## 2. Non-negotiable operating model

Pandora has three separate knowledge layers:

1. **Archive / Event History** — append-only evidence of what happened; never casually deleted.
2. **Working Intelligence** — hypotheses, patterns, confidence changes, relationships, recommendations, and candidate lessons that may evolve automatically.
3. **Canonical Memory** — evidence-backed truth allowed to drive governed execution. Canonical promotion remains review-gated under the current operating contract.

A new datum may immediately change working awareness, but it must not silently overwrite canonical truth.

Status must always distinguish: documented → implemented → tested → deployed → production-verified.

Every meaningful incoming event is normalized into an append-only event record with:

## 6. Compounding intelligence model

Pandora learns five durable memory classes:

1. **Fact memory** — what is currently true, with provenance and verification time.
2. **Decision memory** — what was decided, why, by whom, constraints, and supersession state.
3. **Procedural memory** — sequences of actions that repeatedly work, including prerequisites and proof gates.
4. **Failure memory** — what failed, root cause, repair, prevention, and regression evidence.
5. **Strategic memory** — cross-project patterns, reusable opportunities, systemic risks, and higher-order lessons.

Each durable item should support confidence, provenance, last verification, supersedes/superseded-by links, usage count, outcome evidence, sensitivity, namespace, and refresh/expiry policy where appropriate.

## 7. Evidence hierarchy

Pandora should weight knowledge roughly in this order:

1. production-verified provider-native evidence;
2. provider-native deployment/database/runtime verification;
3. automated test evidence bound to exact source;
4. independent review bound to exact source/evidence;
5. source inspection / deterministic analysis;
6. documented owner decision;
7. sourced external research;
8. conversation-derived inference;
9. model speculation — never canonical by itself.

Contradictory newer verified evidence must correct canonical state while preserving provenance/history.
